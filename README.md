# PARTNER NOTE

매장 파트너를 위한 통합 업무 보조 **연구용 인터랙티브 프로토타입**입니다.

음료 검색 → 온도·사이즈별 레시피 → 연결 부재료 → 작업 상태별 내부품질기한 → NOW TAG 생성으로 이어집니다.

## 실행

Node.js 22 이상 권장. 저장소 루트에서 실행하세요.

```sh
npm ci
npm run dev
```

표시된 로컬 URL을 브라우저에서 엽니다. 서버가 없는 앱이므로 계정·API 키가 필요하지 않습니다.

```sh
npm test
npm run build
npx vite preview --host 127.0.0.1
```

`dist/`에 정적 배포 파일이 생성됩니다. GitHub 저장소 업로드와 웹사이트 배포는 별개입니다.

## 기술과 파일 구조

React 19 · TypeScript · Vite 6 · Lucide React · CSS · localStorage.

| 파일                   | 역할                                                  |

| `src/model.ts`         | Drink / Recipe / Step / Ingredient / QualityRule 타입 |
| `src/seed.json`        | 사용자 자료를 구조화한 시드 데이터                    |
| `src/logic.ts`         | 통합 검색, 날짜 계산, 규칙 선택, 불러오기 검증        |
| `src/main.tsx`         | 화면, 레시피, 관리 편집기, NOW TAG 컴포넌트           |

## 주요 기능

- 11개 음료: 현장 메모 7개 + 프로모션 3개 + 추가 이미지의 차이 티 라떼.
- 음료명·영문명·마킹명·부재료·별칭 검색, 유형 필터, 빈 결과, 최근 조회.
- HOT/ICED 및 온도별 사이즈 제약, 실제 선택 수량 강조.
- 자몽허니 블랙티 TRENTA 별도 절차, 코르타도 HOT/Short, 더블샷 ICED/7oz 및 얼음 커스텀 안내.
- 36개 관련 부재료, 작업 상태별 독립 규칙과 변경 예시.
- 출처·검증 상태·시행일·기간 표시, 미등록/적용 제외 구분.
- NOW TAG 날짜 모드 3종, 요일색 숫자택·날짜택·수기 정보, 시연 결과 저장.
- 규칙이 없거나 같은 조건에서 충돌하면 계산 차단. 입력 변경 시 이전 결과 초기화.
- 로컬 음료·부재료 추가/수정, JSON 백업·복원, 확인 후 초기화.

## 데이터 편집

각 상세 화면의 편집 버튼 또는 **데이터 관리**를 사용하세요. 이름·마킹명/별칭은 입력 폼에서, 제조 단계는 추가·삭제·위아래 이동 버튼으로 수정할 수 있습니다. 온도·사이즈·사이즈별 수량·원재료 ID 연결·프로모션·작업별 규칙·출처·시행일은 같은 편집기의 구조화 JSON에서 편집합니다. 전체 JSON 편집도 지원합니다.

- `availableTemperatures`: `HOT`, `ICED` 배열.
- `availableSizesByTemperature`: 온도별 제공 사이즈 배열.
- `recipes`: `drinkId`, `temperature`, `size`로 구분. `default`는 기본 절차, `TRENTA`는 전용 절차.
- `quantityBySize`: `{ "T": 2, "G": 3, "V": 4 }`처럼 저장합니다. 미확인 수량은 채우지 않습니다.
- `ingredientId`, `relatedIngredientIds`: 부재료 ID로 관계를 연결합니다. 제조 부재료의 원재료 연결도 같은 구조를 사용합니다.
- 규칙은 서로 다른 `id`로 추가합니다. 개봉/소분 규칙을 하나로 덮어쓰지 마세요.
- `effectiveFrom`: 시작일 포함, `effectiveUntil`: 종료일 미포함. 실제 시행일을 모르면 `null`입니다.
- `tagType`: `number`, `date`, `both`, `handwritten`. 기간 단위만으로 결정하지 않습니다.
- `noRuleStates`: 원문에 적용 제외로 명시된 상태입니다. 자료 미등록과 구별합니다.

불러오기는 버전·배열·필수 필드·ID 중복·참조·기한·제조 수량·적용 기간을 검증한 뒤 검토 화면을 엽니다. 검토 후 저장하기 전에는 기존 데이터가 바뀌지 않습니다. 사용자 편집은 `partner-note.v1`, 최근 조회는 `pn-recent`, 택 이력은 `pn-tags`로 해당 브라우저에만 저장됩니다. 시드 파일은 수정되지 않습니다. 초기화는 확인 후 데이터베이스를 시드로 복원하며 최근 조회와 시연 택 이력은 유지합니다.

## 데이터와 검증 상태

시드의 어떤 수치도 최신 공식 운영 기준으로 인증하지 않습니다. 연구 기준표 10개 품목과 첨부 이미지에서 판독한 관련 기준을 출처별로 구분했습니다. 프로모션은 연도 확인 필요·현재 판매 미확인으로 표시합니다. 원본 이미지 자체는 서비스 UI나 저장소에 포함하지 않았습니다.

원료 개봉 3개월과 프라푸치노 로스트 믹스 제조 48시간은 작업 상태가 다릅니다. 제로클래식시럽 14일 → 21일은 변경 이력 UI 예시이며 실제 시행일은 미확인입니다. 제조 부재료의 실제 배합 구성은 자료가 없어서 임의 연결하지 않았습니다.

## NOW TAG 계산 정책

운영용 확정 계산은 차단하고 **시연용 계산 결과**만 생성합니다.

- 시간: 실제 경과 시간을 더합니다.
- 일: 로컬 달력일을 더하고 시각을 유지합니다. 작업일 포함 선택 시 `N-1`일을 더합니다.
- 개월: 같은 날짜로 월을 더하되 대상 월에 그 날짜가 없으면 말일로 보정합니다.
- 규칙 선택은 작업 시작 날짜를 기준으로 합니다. 날짜가 없는 연구/이미지 규칙은 데모 후보로만 사용합니다.
- 내일 오픈 시각은 설정 가능한 참고값입니다. 영업시간 예외를 실제 정책으로 적용하지 않습니다.
- 숫자택: 월~일 1~7 데모 매핑. 월 주황, 화 노랑, 수 초록, 목 하늘, 금 남색, 토 보라, 일 빨강.
- 각 규칙의 `numberCode`가 있으면 사용하며 기본 매핑과 색상은 `logic.ts` 설정으로 분리했습니다.
- `dateFields`와 `dateFormat`은 교체 가능한 메타데이터로 저장합니다. 라벨은 규칙의 `dateFormat`을 기준으로 날짜만/시간 포함을 구분하며, 데모 선택으로 전환할 수 있습니다. 라벨 밖의 접힌 계산 근거에는 전체 작업 일시와 기한 일시가 표시됩니다. 날짜만 표기해도 실제 계산 시각은 바뀌지 않습니다.

## 범위와 확장

여러 직원 동기화, 역할별 권한, 공식 기준 서버, 프린터 연동, 공식 운영용 라벨 출력은 구현하지 않았습니다. 인증·출처 문서 연결·기준 승인·품목 SKU 분리·품목별 동적 날짜 필드/서식·확장형 폼 편집기를 후속으로 추가할 수 있습니다. 외부 Google Fonts 연결이 없으면 시스템 글꼴로 동작합니다.

날짜택 미리보기에는 개봉일/소분일/제조일과 사용기한이 실제 기입 형식으로 표시되며, 기입 범위를 명시합니다. 저장한 시연 결과에는 선택한 표기 범위와 라벨 표시값도 함께 보관합니다.
